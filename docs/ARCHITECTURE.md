# Architecture

MacGuard is split into a framework (`MacGuardKit`) that contains all models, engine code, persistence, and the main-actor app state, and a thin app target (`MacGuard`) that contains SwiftUI views and resources. The test target hosts tests in the app and imports the framework with `@testable`.

## Data flow

```
SwiftUI view
   │  async call / @Published observation
   ▼
AppState (@MainActor)
   │  actor method
   ▼
Engine actor (FileScanner / DuplicateFinder / Cleaner / Organizer / StorageAnalyzer)
   │  FileManager, CryptoKit, Foundation
   ▼
Result models ──► AppState ──► SwiftUI
   │
   └──► Persistence actors (SettingsStore / HistoryStore / RuleStore / Vault)
```

Views never touch the filesystem directly. They call `AppState` methods, which delegate to actors and publish results. This keeps the main thread free and makes the destructive paths easy to audit.

## Safety gates

Every candidate file passes through `PathSafety`:

1. **Hard-protected paths** — system, privacy, keychain, mail, messages, photos, calendars, Safari, containers, group containers, TCC, SSH, GPG, and MacGuard's own data.
2. **Category roots** — a cache file must be under `~/Library/Caches`; a Trash item must be under `~/.Trash`; an installer must be under an allowed download location and have an allowed extension.
3. **Top-level-only rules** — Trash and Downloads only expose top-level items. Nested files are not offered.
4. **Exclusions** — user-defined folders are skipped entirely.
5. **Symlink rejection** — symbolic links are never scanned or removed.
6. **Size and age gates** — large files and old files must meet the configured thresholds.
7. **Second-pass validation** — `Cleaner.validate` repeats the checks at execution time.

The organizer applies a similar gate to destinations and refuses to overwrite existing files.

## Concurrency model

| Type | Isolation | Notes |
| --- | --- | --- |
| `AppState` | `@MainActor` | Publishes view state, coordinates tasks |
| `FileScanner` | actor | Sequential roots, cancellable, progress stream |
| `DuplicateFinder` | actor | Four concurrent hashes, size prefilter |
| `StorageAnalyzer` | actor | Three concurrent directory measurements |
| `Cleaner` | actor | Sequential moves, partial failure collection |
| `Organizer` | actor | Preview is read-only; apply and undo are recorded |
| `Vault` | actor | Manifest and file moves are serialized |
| `HistoryStore` | actor | Newest 200 records, atomic writes |
| `SettingsStore` | actor | Atomic writes, safe defaults |
| `RuleStore` | actor | Atomic writes, default rules |

Progress callbacks are `@Sendable` and hop to the main actor. Scans use `Task.checkCancellation()` and throw `CancellationError`.

## Persistence

All state is local JSON in `~/Library/Application Support/MacGuard`:

- `settings.json` — preferences, thresholds, exclusions, protected paths, schedule.
- `history.json` — newest 200 operations, each with item paths and sizes.
- `rules.json` — organization rules.
- `Vault/manifest.json` — vault entries and original paths.
- `Vault/<operation-id>/` — cleaned files awaiting restore or purge.

Writes use `Data.write(to:options: .atomic)`. Decode failures fall back to safe defaults rather than crashing. The vault is inside a hard-protected path, so no scan can offer its contents for removal.

## Performance choices

- Streaming SHA-256 with 4 MB chunks; files are never fully loaded.
- Duplicate detection groups by size before hashing.
- Directory scans use `FileManager.enumerator` and only read the resource keys needed.
- Progress updates are throttled to every 250 files.
- Scans yield to the cooperative thread pool periodically.
- A 200k item cap per category prevents runaway scans.
- `largestDirectories` measures at most three folders concurrently.

## Testing strategy

The test target covers:

- Byte formatting and date formatting.
- Path safety: protected paths, category roots, top-level rules, thresholds, exclusions, extra protections.
- SHA-256 known-answer and file/data equivalence.
- Duplicate grouping and duplicate-selection safety.
- Vault move/restore/purge and history persistence.
- Settings and rule round-trips.
- Organizer preview/apply/undo and collision handling.
- Storage snapshot and record JSON round-trips.

SwiftUI rendering is not unit-tested. The views are kept presentational and delegate all decisions to `AppState`.

## Build system

The `.xcodeproj` is committed and generated by `scripts/generate_project.py`. The generator uses deterministic UUIDs derived from object keys, so regenerating after adding a file produces a stable project. The shared scheme includes the app and test targets.

Targets:

- `MacGuardKit` — framework, macOS 14.0, Swift 5.0.
- `MacGuard` — application, hardened runtime, AppIcon, Info.plist, entitlements.
- `MacGuardTests` — unit test bundle hosted by the app, `TEST_HOST` and `BUNDLE_LOADER` set.

## Limitations

- The sandbox used to author this repository is Linux; the Xcode build was not run here.
- Full Disk Access may be required to see every protected system location.
- APFS clones and snapshots can make allocated sizes differ from reclaimable space.
- Moving files to the Trash does not free space until the Trash is emptied.
- Scheduled scans run only while the app is open; there is no background daemon.
